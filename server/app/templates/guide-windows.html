Windows 客户端 · 开发迭代教程

下载 Windows 端源代码（zip）

教你用 Electron + 原生外壳 继续开发这个 Windows 客户端：装依赖、跑起来、改界面、打包、发新版让客户端 OTA 自动升级。

这个客户端是「原生桌面外壳 + 站点实时内容」：窗口、标题栏、工具栏、侧栏、菜单、OTA 升级都在源码里，页面内容直接加载 your-server.example.com 真实站点。所以大部分「改界面」其实是改站点网页，只有改外壳/升级逻辑才需要动这份源码。

0. 一句话理解这个项目

客户端 = Electron 主进程（main.js，管窗口/菜单/下载/升级） + 外壳页面（shell.html 等，管标题栏/工具栏/侧栏） + 内容视图（加载站点真实页面）。改窗口、工具栏、升级逻辑 = 改这份源码；改页面内容 = 改站点（server/ 里的 Flask 代码和模板）。

1. 装依赖、跑起来

# 进入解压后的 desktop 目录
cd teaching-system-windows-source/desktop

# 国内镜像（否则 Electron 二进制下载极慢/失败）
export ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
export ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"

# 装依赖
npm install

# 直接跑起来（开发模式）
npm start

跑起来后会看到一个无边框的窗口，标题栏、工具栏、侧栏都是源码画的，中间加载的是真实站点。

4. 打包（安装版 + 绿色版）

npm run dist

产物在 desktop/dist/：

  • 教学管理系统-安装版-x.x.x.exe — NSIS 安装包（可选安装目录、建快捷方式）
  • 教学管理系统-绿色版-x.x.x.exe — 免安装单文件

打包报 Cannot create symbolic link：electron-builder 的 winCodeSign 缓存含 macOS 符号链接，Windows 非管理员账户解压失败。在 %LOCALAPPDATA%\electron-builder\Cache\winCodeSign\ 下手工放 winCodeSign-2.6.0 目录（含 rcedit-x64.exe 和 windows-10/x64/signtool.exe）即可，或开启 Windows「开发者模式」。

5. 发布新版（让客户端 OTA 自动升级）

改完代码后，把 package.json 里的 version 递增（如 1.3.6 → 1.3.7），重新打包，然后用发版脚本上传并登记：

# 发版脚本会自动：上传 → 算 SHA-512 → 写 app_versions → 标记最新版
export LC_PASS='<你的服务器口令>'

# 安装版（渠道 windows）
python tools/publish_app.py --file "dist/教学管理系统-安装版-1.3.7.exe" \
    --platform windows --version 1.3.7 --notes-file release-notes-1.3.7.txt \
    --name "教学管理系统-安装版-1.3.7.exe"

# 绿色版（渠道 windows-portable）
python tools/publish_app.py --file "dist/教学管理系统-绿色版-1.3.7.exe" \
    --platform windows-portable --version 1.3.7 --notes-file release-notes-1.3.7.txt \
    --name "教学管理系统-绿色版-1.3.7.exe"

发布完成后：

  • https://your-server.example.com/download 立刻显示新版本和两种安装包
  • 已装客户端下次检查时（启动后 8 秒 / 运行中每 6 小时）自动收到更新提示

版本号 version_code 由版本名自动推导（1.3.7 → 1003007，见 db.semver_code），不用手填整数。

也可以走网页后台：登录 → 「管理」→「版本管理」，选平台、上传安装包、填版本名和更新说明，效果一样。

6. OTA 升级是怎么工作的（重点）

启动 8 秒后 / 每 6 小时
      ↓
GET /api/v1/app/version?platform=…&version_code=…
      ↓ 服务端返回 need_update=true
工具栏亮徽标「新版本」+ 系统通知
      ↓ 用户点开
「软件更新」对话框（独立模态窗口）
   ├─ 版本对比 / 更新说明 / 体积 / SHA-512
   ├─ 立即更新 → 下载（进度 + 速度，可取消）
   ├─ 下载完 → 核对磁盘字节数 + SHA-512 → 落地正式安装包
   ├─ 立即安装并重启
   │    ├─ 安装版：pkg /S /currentuser 静默原地覆盖 + 自动重启
   │    └─ 绿色版：PowerShell 等主程序退出 → 原地替换 exe → 重新拉起
   └─ 稍后提醒 / 跳过此版本（可恢复）

渠道区分：安装版走 windows，绿色版走 windows-portable（客户端用 process.env.PORTABLE_EXECUTABLE_FILE 判断），两者各自维护「最新版」，互不干扰。

7. 必知的四个坑（都踩过，别重蹈）

坑说明与对策
「更新完重启还是旧版本」散放副本（dist/win-unpacked 直跑、或把安装目录拷走）不是「受管副本」，升级会把新版本装进标准目录，你启动的那个 exe 一点没变。1.3.6 起客户端会识别这种情况并提示「当前副本无法自动升级」，引导去下载页重下。开发时不要双击 win-unpacked 里的 exe 来测更新。
下载 100% 却卡在「下载中」Electron net 流大文件偶发不派发 end 事件。完成判定要用「已收字节数 ≥ Content-Length」+ 磁盘实际大小核对，另有空闲看门狗兜底。
SHA-512 校验总不通过库和 publish_app.py 统一存 hex（base64 大小写敏感，任何 toLowerCase 都会弄坏）。客户端两种编码都认，但库里只存 hex。
点了「安装」却自己关掉、没升级spawn 失败是异步 'error' 事件，try/catch 抓不到。已挂 onError + 启动握手（确认升级组件已起才退出自己），失败时保持原位并提示原因。

8. 调试与验证

# 打开调试端口后，可用 tools/drive.js 驱动界面
LC_DEBUG_PORT=9222 npm start
node tools/drive.js list
node tools/drive.js eval shell 'document.getElementById("btnMenu").click(); "ok"'

# 抓窗口截图（内容区是原生 WebContentsView，必须用 PrintWindow，别用 CDP 截图）
python tools/shot.py shots/ui.png 1200 3

# 端到端界面验证（断言外壳/侧栏/导航/更新徽标等，结果写 shots/verify/report.json）
node tools/verify.js shots/verify

改完外壳或升级逻辑，发版前务必跑一遍 node tools/verify.js shots/verify，它内置了针对上面四个坑的防回归断言。

9. 技术栈速查

Electron 33 + 原生 WebContentsView（内容区）+ electron-builder 25（NSIS 安装版 + portable 绿色版）；外壳 UI 是纯 HTML/CSS/JS（无框架）；服务端是 Flask + SQLite + Apache/mod_wsgi。App 标识 com.teachingsystem.desktop，安装目录名取 package.json 的 name（teaching-system-desktop），显示名 productName（教学管理系统）。
